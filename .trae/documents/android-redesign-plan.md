# Android 子项目前端整合与简约化改造方案

> 目标：统一 `android-app/` 与主项目 `backup/` 移动端的设计语言，降低视觉噪音，让页面更符合「今天该做什么」的核心诉求。

---

## 1. 现状诊断

### 1.1 项目结构
- `android-app/` 是一个独立的 Vite + React + Capacitor 移动端项目，使用 `zustand` + `persist` 做状态管理。
- 主项目 `backup/` 的移动端代码位于 `components/mobile-app.tsx` 与 `components/views/mobile/*`，基于 Next.js + Tailwind v4 + shadcn/ui。
- 两套代码各自维护状态、样式、组件，存在重复实现，视觉风格也不统一。

### 1.2 当前 Android 前端的主要问题

| 问题 | 表现 | 影响 |
|------|------|------|
| 信息密度过高 | Dashboard 同时展示问候、概览、3 个快捷入口、今日待办、数据洞察、周趋势图、FAB | 用户打开首页后难以快速聚焦今日任务 |
| 视觉噪音多 | 大量渐变背景、阴影、圆角装饰、内联样式 | 风格不够统一，与主项目移动端差异大 |
| 组件复用低 | TabBar、卡片、按钮等多用内联 CSS，没有统一 UI 层 | 维护成本高，交互一致性差 |
| 状态管理冗余 | `android-app/src/store/useStore.ts` 与主项目 `lib/store.ts` 各自维护任务/番茄钟/习惯等数据模型 | 数据模型变更需要改两处 |
| 布局不够移动优先 | 桌面预览使用 `phone-frame`，但在真机上部分元素间距、字号显得拥挤 | 影响 Android 真机体验 |

---

## 2. 设计原则

基于用户偏好与项目既有约束，本次改造遵循以下原则：

1. **以「今天」为首页核心**：首页只展示今日待办、今日专注进度、习惯打卡入口，详细统计放到「数据」页。
2. **减少视觉噪音**：移除多余渐变、阴影、装饰性圆角；优先使用扁平色块与留白区分层级。
3. **统一设计 Token**：颜色、字号、间距、圆角与主项目移动端保持一致。
4. **组件化复用**：把常用元素抽象为 `Button`、`Card`、`ListItem`、`IconButton` 等基础组件。
5. **移动优先**：所有间距、字号、触摸目标优先适配 360–430 px 宽度的 Android 真机。
6. **渐进式整合**：先改造界面与布局，再视情况同步数据模型与共享逻辑。

---

## 3. 整合策略

### 3.1 设计系统对齐

将 `android-app/src/styles/globals.css` 中的 CSS 变量与 Tailwind 主题向主项目移动端靠拢：

- 背景：由渐变/多径向渐变改为纯色或极淡的灰蓝背景（参考主项目 `bg-background`）。
- 卡片：统一为白色/深色卡片，使用 1px 描边或极淡背景区分，**移除阴影**（符合项目约束：shadow-none 风格）。
- 圆角：卡片统一 `--radius-card: 16px`，按钮 `--radius-btn: 12px`。
- 字号：建立 4 级字号规范（标题 18px、正文 14px、辅助 12px、标注 11px）。
- 颜色：保留 `--blue`、`--green`、`--orange`、`--red`、`--purple` 语义色，但降低饱和度，与主项目 shadcn 主题对齐。

### 3.2 基础组件层

在 `android-app/src/components/ui/` 下新增/重构以下组件，替代散落在 CSS 与页面里的内联样式：

| 组件 | 用途 | 关键样式 |
|------|------|----------|
| `Card` | 页面区块容器 | 扁平、圆角 16px、无阴影、可选描边 |
| `IconButton` | 顶部操作按钮 | 40×40 圆形、浅色背景 |
| `TabBar` | 底部导航 | 扁平图标、当前态高亮、无浮层背景 |
| `ListItem` | 任务/习惯列表项 | 左图标/勾选、标题、右状态、点击反馈 |
| `SectionHeader` | 区块标题 | 左标题、右「全部」链接 |
| `EmptyState` | 空状态 | 图标 + 标题 + 辅助文字 |
| `StatCard` | 小数据统计 | 大数字 + 标签、扁平 |

### 3.3 页面布局改造

#### 3.3.1 Dashboard（首页）

**当前问题**：信息堆叠过多。

**改造后结构**：

```
┌─────────────────────────────┐
│ [头像] 问候语        [🔍][🔔] │
├─────────────────────────────┤
│ 今日专注  XX分钟  / 目标     │
│ [开始专注] 按钮              │
├─────────────────────────────┤
│ 今日待办        全部 >       │
│ • 任务 1              [状态] │
│ • 任务 2              [状态] │
│ ...                          │
├─────────────────────────────┤
│ 习惯打卡        全部 >       │
│ ○ ○ ● ○ ...                  │
├─────────────────────────────┤
│ [+] 新建任务 FAB             │
└─────────────────────────────┘
```

**改动点**：
- 移除「数据洞察」与「周趋势图」模块，迁移到「数据/分析」页。
- 移除 3 列快捷入口卡片，改为顶部一条「今日专注进度」横幅。
- 保留「今日待办」与「习惯打卡」，但使用统一 `ListItem` / `Card` 组件。
- FAB 简化为纯色圆形 + 图标，去掉渐变阴影。

#### 3.3.2 Tasks（任务页）

**当前问题**：tab 与 stat 区块占用过多首屏。

**改造后**：
- 顶部仅保留搜索框 + 快速过滤标签（今日/进行中/已完成）。
- 任务列表使用 `ListItem` 组件，一行显示标题、项目色点、截止时间。
- 完成/恢复操作放到左滑或详情页，减少单页按钮数量。

#### 3.3.3 Focus（专注页）

**当前问题**：计时器外圈、光晕、环境音模块等元素堆砌。

**改造后**：
- 页面中央只保留一个简洁的倒计时圆环 + 大时间数字。
- 控制按钮一行 3 个（重置、开始/暂停、完成），统一尺寸。
- 把「环境音」「成就」等辅助功能收到二级抽屉或设置中，不再常驻主界面。

#### 3.3.4 Habits（习惯页）

**当前问题**：习惯卡片与圆点打卡混排，视觉不统一。

**改造后**：
- 使用统一 `ListItem` 列出习惯，右侧显示本周 7 天打卡圆点。
- 点击圆点即可打卡，点击整行进入详情/编辑。

#### 3.3.5 Me（我的页）

**当前问题**：设置项与功能入口堆叠。

**改造后**：
- 按组分隔：账号与同步、外观、数据与隐私、关于。
- 设置项统一使用 24px 水平内边距，符合项目约束。
- 移除装饰性渐变卡片。

### 3.4 TabBar 简化

- 去掉浮起的胶囊式背景、玻璃拟态阴影。
- 改为底部一条细线分隔的扁平 TabBar，图标 22px、标签 10px。
- 当前态仅改变颜色/字重，不使用额外的背景块或投影。

### 3.5 状态管理与代码整合（第二阶段）

- 梳理 `android-app/src/store/useStore.ts` 与 `lib/store.ts` 的数据模型差异。
- 优先统一类型定义（Task、PomodoroSession、Habit 等），可提取到共享的 `types.ts` 或保持两份同步。
- 对于通用工具函数（格式化时间、日期、greeting），统一放到 `android-app/src/lib/` 并从主项目复用逻辑。

## 4. 实施步骤

建议按以下顺序推进，每步完成后可独立验证：

### 阶段一：设计系统（1–2 天）
1. 重构 `globals.css` 变量，移除渐变背景与多余阴影。
2. 更新 `tailwind.config.js` 颜色/字号/间距 token。
3. 创建 `android-app/src/components/ui/` 基础组件：`Card`、`IconButton`、`ListItem`、`SectionHeader`、`EmptyState`、`StatCard`。
4. 重写 `TabBar.tsx`，扁平化样式。

### 阶段二：核心页面改造（2–3 天）
5. 重写 `Dashboard.tsx`，聚焦「今天」。
6. 重写 `Tasks.tsx`，简化列表与过滤。
7. 重写 `Focus.tsx`，简化计时器主界面。
8. 重写 `Habits.tsx` 与 `Me.tsx`，统一列表与设置样式。

### 阶段三：路由与交互补齐（1–2 天）
9. 检查所有二级页面（TaskDetail、Settings、Analytics 等）是否使用新组件。
10. 统一页面转场、按钮点击反馈、空状态。
11. 验证真机/模拟器上的安全区、字体、间距。

### 阶段四：状态模型整合（可选，2–3 天）
12. 对比并统一主项目与 android-app 的 store 类型。
13. 提取可共享的 utility / hooks。
14. 编写简单的类型一致性检查脚本或文档。

## 5. 验收标准

- [ ] Dashboard 首屏只保留问候、今日专注、今日待办、习惯打卡、FAB。
- [ ] 所有卡片/按钮使用新 UI 组件，无内联渐变/阴影装饰。
- [ ] TabBar 扁平化，无浮起胶囊背景。
- [ ] 任务、习惯、设置页面使用统一 `ListItem` / `SectionHeader` 组件。
- [ ] 在 390px 宽模拟器与 Android 真机上无元素截断、重叠或触摸目标过小。
- [ ] 编译无新增 TypeScript 错误，`npm run build` 成功。
- [ ] 与主项目移动端的视觉风格基本一致（颜色、圆角、间距、字号）。

---

## 6. 风险与注意事项

1. **Capacitor 构建产物干扰 Vite 扫描**：已修复 `vite.config.ts` 的 `optimizeDeps.entries`，后续改造需避免在 `android/app/src/main/assets/public/` 中放置新的入口 HTML。
2. **状态不兼容**：若统一 store 类型，需确保持久化数据不损坏，建议加数据迁移逻辑。
3. **主项目 Tailwind v4 vs android-app Tailwind v3**：两者配置语法不同，不能直接复制配置，但设计 token 可以手动同步。
4. **改动范围大**：建议每改造完一个页面就进行真机预览，避免最后集中返工。
