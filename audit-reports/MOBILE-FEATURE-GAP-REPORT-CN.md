## 二、移动端现状盘点（22 页面实证）

**任务域**（最完整）：列表/看板/时间线/**四象限**四视图、批量操作、任务模板、智能筛选 5 项、快速添加（共享 NLP 解析器）、子任务全链路、星级、优先级色条、回收站、搜索页、项目页
**专注域**：三模式计时（渐变进度环）、任务联动、专注预设、白噪音（共享 24 音色引擎适配）、严格模式+本轮锁定、专注屏蔽页、时间追踪页
**习惯/目标**：打卡（周历+批量补卡+量化环）、冻结、连胜（共享调度感知引擎）、目标里程碑
**数据/系统**：统计（趋势/分布/周柱图金色今日/完成率）、成就页、等级（共享 20 级）、手账、日历（ICS 导出）、纪念日、时间块、同步（OSS/WebDAV）、通知中心、语音快速捕获（原生 STT 桥）、偏好

**已通过 `shared/core/` 统一**（无漂移风险）：等级曲线、色板、习惯频率、连胜引擎、NLP 解析、重复推进、XP 规则、音效引擎。

## 三、差距详表与建议

### P0-1 升级庆祝弹窗（工作量：小 · 建议本轮）
- **现状**：android `gamification.ts` 的 `gainXP` 加经验后无任何升级反馈；桌面已有 `levelUpCelebration` 瞬态 + `LevelUpModal`（奖杯渐变卡 + Lv/称号 + 入场动画）。
- **建议**：移动端同款——`useStore.gainXP` 内检测跨级置位瞬态状态，`App.tsx` 挂全局弹层（复用 framer-motion，与底栏滑动砖同一 motion 语言）。等级阈值已共享，跨级判定口径两端一致。

### P0-2 ICS 日历订阅（工作量：小-中）
- **现状**：`lib/ics.ts` 仅 `buildICS/downloadICS/exportTaskToICS/exportTimeBlocksToICS`（纯导出）；桌面有 `calendar-subscriptions`（订阅 URL 管理 + ICS 拉取解析 + 事件入日历）。
- **建议**：把桌面 ICS **解析器**上移 `shared/core/ics-parse.ts`（RRULE 展开为简化版），移动端 Calendar 页加"订阅管理"入口（URL 列表 + 手动刷新），事件走现有 externalEvents 存储。

### P0-3 生产力评分卡（工作量：小）
- **现状**：Analytics 有专注时长/完成任务/连续打卡三卡 + 周柱图，无综合评分。
- **建议**：把桌面 `productivity-score` 计算上移共享层（输入聚合数据输出 S-D 评分），Analytics 顶部加评分环（MiniRing + 评级字母，环母题又一落点）。

### P0-4 专注声音自动化（工作量：小）
- **现状**：Focus 页手动播/停白噪音；无"开始专注自动播放"、无会话结束自动停、无定时停止。
- **建议**：偏好加 autoPlay 开关（计时开始 → audioEngine 恢复上次音色；结束/暂停 → 停止）+ 定时停止 15/30/60（复用共享睡眠定时语义）。

### P1-5 任务依赖（工作量：中）
- **现状**：`Task` 无 `blockedBy` 字段，完成无拦截。
- **建议**：类型加 `blockedBy?: string[]`；TaskDetail 显示"被 N 个任务阻塞"列表；`toggleTask` 完成时检查未完成的前置并 toast 拦截（严格模式可选）。与桌面字段命名对齐，为未来同步铺路。

### P1-6 分心记录（工作量：中）
- **现状**：严格模式锁定存在，但专注中途切走/解锁无任何记录。
- **建议**：`focus.shield` 的可见性变化（visibilitychange + Capacitor App 状态）记入 `distractions`（时间戳+时长），统计页加"分心次数"卡（金色反向动量：次数下降=进步）。

### P1-7 智能清单对齐（工作量：小）
- **现状**：移动端 5 个筛选 chip 与桌面 7 个智能清单口径不一致（如桌面有"本周""无日期"细分）。
- **建议**：桌面 `smart-lists.ts` 的判定函数上移共享层，两端 UI 各自渲染同一套清单语义。

### P1-8 每日回顾（工作量：中）
- **现状**：Journal 为自由手账；桌面每日回顾=当日数据+心情+感恩三件套，且与统计联动。
- **建议**：移动端晚间（如 21:00 本地通知）触发回顾卡（今日数据摘要 + 心情四选 + 感恩一条），写入 Journal 结构化模板。

### P2（共同缺口或高成本，双方统一排期）
- **多提醒数组**：桌面 3 类提醒 vs 移动端单条；收敛需重写 Android 原生通知调度 + 表单编辑器 + 详情 UI
- **奖励商店 / 呼吸训练 / 农历节假日**：双方共同缺口，桌面侧路线图优先
- **小组件可交互**：Java 层 PendingAction 通道（习惯打卡/开始专注按钮），原生工作量
- **Forest 树成长**：产品决策项（与专注环视觉已有重叠，优先级存疑）

## 四、路线图

**第一批（1-2 天）**：P0-1 升级弹窗 → P0-4 声音自动化 → P0-3 评分卡 → P1-7 智能清单对齐（全部小工作量，纯 JS 层）
**第二批（3-5 天）**：P0-2 ICS 订阅（共享解析器上移）→ P1-6 分心记录 → P1-8 每日回顾
**第三批（1 周+）**：P1-5 任务依赖 → P2 各项（建议与桌面侧合并排期，能共享的实现一律先上移 `shared/core/`）

> 原则提醒：任何新业务规则（评分、智能清单判定、提醒语义）先写进 `shared/core/`，两端 UI 各自消费——这是本轮统一工程定下的规矩，避免制造下一轮漂移。
